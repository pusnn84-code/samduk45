# 가을빛축제

회원 메뉴의 샘목양지 다음에 가을빛축제를 추가합니다. 화면은 승인된 마지막 시안처럼 설명을 줄이고 카드 아래에 작은 🙏 숫자만 표시합니다. 이모티콘 추가 변경은 취소된 상태를 유지합니다.

한국 날짜를 기준으로 공동체가 함께 볼 기도 대상 한 사람을 DB에 보관합니다. 같은 날 다시 열거나 새 대상을 등록해도 오늘의 대상은 바뀌지 않습니다. 다음 날은 전날 대상 이외를 우선해 무작위 선택합니다. 반응은 카드별 회원당 하나이며 요청을 다시 보내도 중복 생성하지 않습니다. 다시 누르면 본인 반응만 취소합니다. 길게 누르기·오른쪽 클릭·Shift+F10으로 참여자 명단을 열 수 있습니다. 화면에는 자세한 조작 설명을 넣지 않습니다.

전체 카드에서 이름·작성자를 검색하고 마을 다음 샘을 고릅니다. 선택 목록은 실제 sams 테이블에서 조회하며 1~5마을만 포함합니다. 마을 변경 시 샘 선택을 초기화합니다. 기존 2·4·5마을의 6샘은 유지합니다. 마을별 현재 샘 수는 5,6,5,6,6입니다.

로그인한 회원은 새 태신자의 이름·샘·기도제목을 등록합니다. 작성자는 세션에서 결정하며 외부에서 작성자나 방문·등록 상태를 지정할 수 없습니다. 같은 샘의 같은 이름이 있으면 먼저 확인합니다. 동명이인 확인 후 별도로 등록할 수 있습니다. 등록 키로 전송 결과가 불명확한 요청의 재시도 중복을 막습니다. 새로 등록한 본인 카드는 내용을 수정할 수 있고, PDF에서 가져온 기존 카드는 관리자만 수정합니다.

방문·교회 등록은 별도 boolean입니다. 일반 회원·부관리자는 자신의 카드라도 현황을 수정할 수 없습니다. 관리자만 체크·해제하며 버전 충돌을 검사합니다. 둘 다 미체크이면 상태 영역 자체가 없습니다. 방문만 체크하면 방문만, 등록만 체크하면 등록만, 모두 체크하면 두 표식을 표시합니다.

데이터: 제공 PDF의 74카드에서 쉼표로 분리된 명시적 이름을 나누어 86항목을 등록했습니다. 원래 기도제목과 작성자·샘을 보존하며 동명이인을 임의로 합치지 않습니다. 기도제목이 여러 사람을 위해 함께 작성된 경우 각각 동일 원문을 연결합니다. 실제 방문·등록 자료가 없어 초기 체크는 모두 false입니다. 원문·등록 SQL은 작업 폴더에 보관하며 배포 파일이나 public 폴더에는 원문 파일을 추가하지 않습니다. 재등록은 source_key 기준으로 기존 수정을 덮어쓰지 않습니다.

DB: drizzle/20261112030000_autumn_light.sql. 세 테이블의 RLS를 켜고 public·anon·authenticated 권한을 회수합니다. 인증된 서버 API만 조회합니다. 응답은 private no-store이며 참여자 목록은 이름만 제공합니다. 전화번호와 계정 식별자는 목록에 전달하지 않습니다.

검증: 가을빛축제 및 메뉴 관련 테스트 24개 통과. 전체 검사 787개 통과·DB 의존 3개 제외 후, 이전 새 글 배지 정책과 불일치하던 테스트 하나의 기대값을 현재 정책에 맞춰 조정하고 해당 묶음 24개를 재검증했습니다. 최종 소스 TypeScript 검사 통과. Windows 샌드박스에서 junction 생성 및 빌드 폴더 mkdir EPERM으로 로컬 Next 운영 빌드는 완료하지 못했습니다. 기본 Turbopack과 별도 출력 폴더의 webpack에서 동일한 파일 권한 제한을 확인했습니다. 이 제한을 앱 코드의 성공적인 운영 빌드로 기록하지 않습니다.

DB 구조 적용 및 86항목 등록을 Supabase 화면에서 확인했습니다. 운영 공개와 실제 화면 검증은 Vercel 업로드·빌드가 성공한 뒤에만 완료로 기록합니다. 앞서 대기 중인 기도요청 공개 범위·간결한 달력·규칙적인 메뉴 색 배열도 동일 소스에 포함됩니다.
